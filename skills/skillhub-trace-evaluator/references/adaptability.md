# Adaptability（适用性）

2 个子项：`boundary`、`trigger`。全部须评分；`score` ∈ `(0, 5.0]`；缺失给 1.0–2.0。

## boundary（能力边界）

清晰声明能做什么、不能做什么。

| 分 | 标准 |
|----|------|
| 5 | 清晰说明能做/不能做；明确适用场景和限制；有输入输出约束 |
| 4 | 大部分能力边界有说明，少量限制未明确 |
| 3 | 部分能力边界有说明，但不够全面 |
| 2 | 能力边界说明很少，用户容易误解 |
| 1 | 没有任何能力边界说明 |

## trigger（触发方式）

调用条件明确、合理、易命中。

| 分 | 标准 |
|----|------|
| 5 | 明确如何触发；支持哪些调用方式；有触发示例；条件清晰无歧义 |
| 4 | 触发方式基本明确，有示例但不够丰富 |
| 3 | 有触发说明但不够清晰，部分场景模糊 |
| 2 | 触发方式说明不完整，用户需要猜测 |
| 1 | 没有说明如何使用 |

每子项：`reason` + `userReason`。维度级填写 `reason` / `userReason`。

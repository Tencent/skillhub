# Reliability（可靠性）

3 个子项：`stability`、`func`、`errorHandling`。全部须评分；`score` ∈ `(0, 5.0]`；缺失给 1.0–2.0。

## stability（运行稳定性）

相同输入多次执行不崩溃、核心输出一致。

| 分 | 标准 |
|----|------|
| 5 | 有重试机制、超时处理、错误恢复；运行稳定可靠 |
| 4 | 基本稳定，有一定容错机制 |
| 3 | 大部分情况稳定，但缺少部分容错机制 |
| 2 | 稳定性较差，容易出现未处理的异常 |
| 1 | 无任何容错机制、容易崩溃 |

## func（功能完善性）

声明的功能全部实现，无「空壳」。

| 分 | 标准 |
|----|------|
| 5 | 核心功能完整齐全；支持多种输入格式；有参数校验和默认值处理 |
| 4 | 核心功能完整，少量边缘功能缺失 |
| 3 | 主要功能可用，但部分重要功能缺失 |
| 2 | 仅实现部分核心功能 |
| 1 | 核心功能缺失、仅有骨架代码 |

## errorHandling（异常处理）

异常输入时优雅降级，给出有意义的错误提示。

| 分 | 标准 |
|----|------|
| 5 | 错误提示友好；有明确的错误码；能引导用户修正 |
| 4 | 异常处理较完善，错误提示基本友好 |
| 3 | 有基本的异常处理，但提示不够友好 |
| 2 | 异常处理不完善，部分错误无提示 |
| 1 | 异常时无提示或提示不可读 |

每子项：`reason`（开发者）+ `userReason`（用户，质量评价）。维度级填写 `reason` / `userReason`。

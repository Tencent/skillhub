# Convention（规范性）

4 个子项：`progressive`、`structure`、`docQuality`、`antiPatternFaq`。全部须评分；`score` ∈ `(0, 5.0]`；缺失给 1.0–2.0。

## progressive（渐进式披露）

| 分 | 标准 |
|----|------|
| 5 | 从简单到复杂分层；可按需深入；不信息过载 |
| 4 | 信息层次较清晰，大部分展开顺序合理 |
| 3 | 有一定层次感，部分组织不够合理 |
| 2 | 信息组织较混乱，层次不清晰 |
| 1 | 所有信息堆砌，没有层次感 |

## structure（结构清晰）

| 分 | 标准 |
|----|------|
| 5 | 目录合理、模块清晰、命名规范、易于导航 |
| 4 | 结构基本清晰，少量可优化 |
| 3 | 结构尚可，部分模块划分不合理 |
| 2 | 结构较混乱，难找关键内容 |
| 1 | 文件杂乱无章 |

## docQuality（文档质量）

| 分 | 标准 |
|----|------|
| 5 | 多个典型用例与输出样例；有最佳实践；内容实用 |
| 4 | 有用例和样例，覆盖较全面 |
| 3 | 有少量案例，覆盖不够全面 |
| 2 | 仅有简单示例，缺实际场景 |
| 1 | 无任何使用案例或输出样例 |

## antiPatternFaq（反模式与 FAQ）

| 分 | 标准 |
|----|------|
| 5 | 明确应避免的用法与常见错误；FAQ 覆盖高频问题 |
| 4 | 有反模式说明和 FAQ，覆盖主要问题 |
| 3 | 有少量反模式提示或 FAQ |
| 2 | 仅有简单警告，缺具体说明 |
| 1 | 无任何反模式说明或 FAQ |

每子项：`reason` + `userReason`。维度级填写 `reason` / `userReason`。
